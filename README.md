# netspeed

Утилита для замера скорости скачивания со своего компьютера. Она 10 раз подряд
скачивает один и тот же файл и печатает среднее время запроса, объём и
скорость в МБ/с.

Нужен только Python 3.10+, сторонних зависимостей нет.

## Запуск

```bash
git clone https://github.com/delawer33/netspeed.git
cd netspeed
uv run netspeed https://eoimages.gsfc.nasa.gov/images/imagerecords/57000/57752/land_shallow_topo_8192.tif
```

Без [uv](https://docs.astral.sh/uv/):

```bash
python -m venv .venv && . .venv/bin/activate
pip install .
netspeed https://eoimages.gsfc.nasa.gov/images/imagerecords/57000/57752/land_shallow_topo_8192.tif
```

Пример вывода (реальный прогон, снимок NASA на 27,8 МБ):

```
[ 1/10]    27.80 МБ   23.313 с      1.19 МБ/с
[ 2/10]    27.80 МБ   31.625 с      0.88 МБ/с
...
[10/10]    27.80 МБ   12.239 с      2.27 МБ/с

Успешных запросов:  10 из 10
Скачано:            277.98 МБ (277979680 байт)
Среднее время:      22.867 с
Скорость:           1.22 МБ/с (9.7 Мбит/с)
```

Это скорость до конкретного сервера, а не «скорость интернета» вообще. Чем
дальше сервер, тем ниже цифра. Для замера канала до провайдера берите файл на
CDN поближе к себе.

### Параметры

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `URL` | — | `http://` или `https://` адрес тяжёлого файла, лучше 10 МБ и больше |
| `-n`, `--requests` | 10 | число последовательных запросов |
| `--timeout` | 60 | предел на один запрос, с |

Коды выхода: `0` — все запросы успешны; `1` — часть запросов упала или
серию прервали Ctrl+C, итог посчитан по успешным; `2` — ни одного успешного
запроса.

## Как считается

- **Время запроса** — от отправки запроса до последнего байта тела, включая
  DNS и TCP/TLS-рукопожатие. Не время до заголовков:
  [ADR 1](docs/adr/0001-time-to-last-byte.md).
- **Объём** — сумма байт тела по успешным запросам.
- **Скорость** — суммарный объём / суммарное время, а не среднее скоростей
  отдельных запросов: [ADR 2](docs/adr/0002-ratio-of-sums.md). На прогоне
  выше среднее скоростей дало бы 1,49 МБ/с вместо реальных 1,22.
- **МБ** — 10⁶ байт, как у провайдеров. В скобках та же скорость в Мбит/с,
  потому что тарифы пишут в них.
- Запросы уходят без сжатия и с `Cache-Control: no-cache`. Оборванное или
  пустое тело считается ошибкой, а не быстрым запросом:
  [ADR 3](docs/adr/0003-honest-bytes.md).

Словарь терминов — в [CONTEXT.md](CONTEXT.md).

## Устройство

```
src/netspeed/
  measure.py   fetch(url) -> Sample: один запрос, время до последнего байта
  stats.py     summarize(samples) -> Summary: среднее время, объём, скорость
  cli.py       разбор аргументов, серия запросов, вывод, код выхода
```

HTTP — `urllib` из стандартной библиотеки, чтобы утилиту не нужно было ставить
вместе с зависимостями: [ADR 4](docs/adr/0004-stdlib-only.md).

## Тесты

```bash
uv run pytest
uv run ruff check . && uv run mypy
uv run pre-commit install   # те же проверки и gitleaks перед каждым коммитом
```

Тесты поднимают локальный HTTP-сервер с маршрутами под каждый сценарий: тело,
которое приходит медленнее заголовков, оборванное тело, ошибки через раз.
Ключевые тесты:

| Тест | Что проверяет |
|---|---|
| `test_time_includes_body_download_not_just_headers` | время считается до конца тела, а не до заголовков |
| `test_speed_is_total_bytes_over_total_time_not_mean_of_speeds` | скорость — объём / время, а не среднее скоростей |
| `test_runs_ten_sequential_requests_by_default` | 10 запросов, ни одного параллельного |
| `test_truncated_body_is_failure_not_sample` | оборванное тело не засчитывается |
| `test_partial_failure_reports_successes_and_exits_1` | итог по успешным, код выхода 1 |
| `test_lines_keep_request_order_when_piped` | при выводе в файл строки не перемешиваются |

## Что сознательно упрощено

- **Один поток.** Speedtest-сервисы качают в 4–16 соединений и выбирают
  ближайший сервер. Здесь одно соединение до указанного URL, поэтому на
  быстром канале цифра будет ниже. Если нужно, следующий шаг — параллельная
  серия поверх того же `fetch`.
- **Рукопожатие входит во время.** `urllib` не держит соединение, поэтому
  каждый запрос заново проходит DNS и TCP/TLS. До сервера из примера это
  около 1 с (замер `curl -w %{time_appconnect}`) при 12–48 с на запрос, то
  есть скорость занижена на 2–8%. Чем тяжелее файл, тем меньше эта доля.
- **Нет отсечения выбросов.** Все запросы входят в итог одинаково. Медиана и
  перцентили пригодятся, если результаты начнут куда-то складывать.
- **Только загрузка.** Скорость отдачи не меряется.
- **`no-cache` — просьба, а не гарантия.** CDN может её проигнорировать.
- **Вывод — текст для человека.** Машиночитаемый формат (`--json`) не сделан,
  потому что пока нет потребителя.
