# 3. Считаем только честно скачанные байты

## Контекст

Байты, по которым считается скорость, могут быть не теми, что прошли через
канал:

- **сжатие**: HTTP-клиент с `Accept-Encoding: gzip` получает меньше байт,
  чем отдаёт после распаковки, и скорость завышается;
- **кэш**: прокси или CDN по пути может отдать ответ из кэша, и замеряется
  не тот путь;
- **обрыв**: соединение рвётся на середине, и неполное тело засчитывается
  как полноценный быстрый запрос.

## Решение

- Запрос уходит с `Accept-Encoding: identity`, `Cache-Control: no-cache`
  и `Pragma: no-cache`.
- Если в ответе есть `Content-Length`, а получено другое число байт, запрос
  неудачный. Пустое тело — тоже неудачный запрос.
- Неудачные запросы в статистику не идут, печатаются в stderr и дают код
  выхода 1. Если ни одного успешного запроса нет, код 2.

## Последствия

Тесты `test_asks_for_uncompressed_uncached_response`,
`test_truncated_body_is_failure_not_sample`,
`test_partial_failure_reports_successes_and_exits_1`.

`no-cache` — просьба, а не гарантия: CDN может её игнорировать. Для замера
«до своего провайдера» это приемлемо, поскольку CDN обычно ближе всего к
пользователю.
